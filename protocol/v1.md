# WSA Bluetooth Bridge protocol v1

The development transport is newline-delimited JSON (JSONL). One JSON object per line.

## Host greeting

```json
{"type":"hello","protocol":1,"capabilities":["ble.scan"]}
```

## Commands

### Ping

```json
{"type":"ping"}
```

Response:

```json
{"type":"pong"}
```

### Start BLE scan

```json
{"type":"scan.start"}
```

The host responds with a state event and then zero or more scan results.

### Stop BLE scan

```json
{"type":"scan.stop"}
```

## Events

### Scan state

```json
{"type":"scan.state","state":"started"}
```

### Scan result

```json
{
  "type":"scan.result",
  "address":"A1B2C3D4E5F6",
  "rssi":-62,
  "name":"Example",
  "serviceUuids":["0000180f-0000-1000-8000-00805f9b34fb"],
  "timestamp":"2026-10-05T12:00:00.0000000Z"
}
```

## Design rules

- Protocol is versioned from the first packet.
- Unknown commands must return an error instead of being ignored.
- BLE addresses are represented as 12 uppercase hexadecimal digits without separators.
- The current PoC is read-only and exposes scanning only.
- Pairing, connection, GATT and notification messages will be added in later protocol revisions.
