# WSA Bluetooth Bridge protocol v1

The development transport is newline-delimited JSON (JSONL). One JSON object per line.

## Host greeting

```json
{"type":"hello","protocol":1,"capabilities":["ble.scan","ble.connect","gatt.discover","gatt.read"]}
```

## Commands

### Ping
```json
{"type":"ping"}
```

### Start / stop BLE scan
```json
{"type":"scan.start"}
{"type":"scan.stop"}
```

### Connect / disconnect BLE device

```json
{"type":"device.connect","address":"A1B2C3D4E5F6"}
{"type":"device.disconnect"}
```

The host performs an uncached GATT service request while connecting. A successful `device.connection` with `gattStatus: Success` therefore proves real BLE/GATT communication, not just discovery.

### Discover GATT services

```json
{"type":"gatt.discover"}
```

The response contains services and characteristics with UUIDs and characteristic properties.

### Read a GATT characteristic

```json
{
  "type":"gatt.read",
  "service":"0000180f-0000-1000-8000-00805f9b34fb",
  "characteristic":"00002a19-0000-1000-8000-00805f9b34fb"
}
```

A successful response returns `valueHex`.

## Important events

```json
{"type":"scan.state","state":"started"}
```

```json
{
  "type":"scan.result",
  "address":"A1B2C3D4E5F6",
  "rssi":-62,
  "name":"Example",
  "serviceUuids":["0000180f-0000-1000-8000-00805f9b34fb"]
}
```

```json
{
  "type":"device.connection",
  "state":"connected",
  "gattStatus":"Success",
  "serviceCount":3
}
```

## Design rules

- Protocol is versioned from the first packet.
- Unknown commands return an error.
- BLE addresses are 12 uppercase hexadecimal digits without separators.
- Current scope is BLE scan, connect, GATT discovery and GATT read.
- Writes and notifications are intentionally deferred until the read path is proven.
